# Живая демонстрация и клиентская приёмка

Клиентская приёмка: **PENDING, продолжается**. Демонстрация потенциальному заказчику
**BLOCKED** из-за [URALBYTE-9](https://tracker.yandex.ru/URALBYTE-9), до повторной проверки.
Исходная инженерная проверка MVP в кластере: **Checker PASS, Reviewer APPROVE**;
наблюдавшиеся результаты: [deployment/bigbang.md](deployment/bigbang.md).
Эти вердикты не относятся к новой доработке. Локальные автотесты не заменяют доступного Telegram-бота,
реальный Yandex API и Kubernetes bigbang в РФ. Заполняйте результаты только наблюдавшимися фактами.

## Инженерная проверка в Kubernetes

Записать дату UTC, Git revision, cluster context/регион, настроенный часовой пояс и Telegram ID
без токенов, паролей и содержимого приватной памяти.

1. `kubectl --context yc-big-bang -n chief-ai-assistant get pods,pvc`: app 3/3 Ready, БД Ready, PVC Bound; `/health` возвращает ok.
2. `scripts.probe_ai`: реальная модель, native/json protocol, tool roundtrip и оба
   embeddings прошли. При выборе JSON приложить причину и успешный повторный probe.
3. Telegram: «напомни через две минуты проверить демонстрацию». Убедиться, что
   сообщение создано без вопроса, затем пришло реальное напоминание. Записать срок,
   время получения и задержку. Scheduler добавляет указание задержки после 10 секунд.
4. Telegram: «запомни: руководитель проекта Альфа — Иванов»; отдельным сообщением
   спросить руководителя. Сохранить противоречащую запись и проверить обе версии.
5. Загрузить текстовый PDF и спросить факт из него. Ответ содержит название/страницу;
   вопрос вне содержания получает сообщение о недостатке оснований.
6. Подготовить встречу, проверить канонические дату/время/описание, подтвердить.
   Сообщение прямо говорит о симуляции; повтор кнопки не выполняет действие снова.
7. Подготовить другое pending approval и поручение; выполнить `kubectl --context yc-big-bang -n chief-ai-assistant rollout restart deployment/assistant`.
   Спросить сохранённый факт, подтвердить прежнее approval; проверить сохранность PDF.
8. Остановить background перед сроком поручения; после срока запустить снова.
   Получить просроченное напоминание с задержкой. Не удалять volumes.
9. Запустить `scripts.benchmark`, сохранить JSON/Markdown с реальными AI calls,
   токенами, ставками, валютой и датой. Разделить индексацию PDF и вопрос; скопировать
   итоговую таблицу в README. Неполные показатели обозначить явно.

## Продолжение приёмки: URALBYTE-8

Первая часть клиентской приёмки выявила UX/безопасностные замечания. Они не блокируют
инженерную готовность исходного MVP, но должны быть устранены до демонстрации заказчику.
Отдельная [доработка URALBYTE-8](https://tracker.yandex.ru/URALBYTE-8) и её
[согласованный план](followups/URALBYTE-8.md) проходят обычный инженерный цикл.
Общий клиентский вердикт остаётся **PENDING**: приёмка продолжается.

| Проверка доработки | Состояние |
|---|---|
| Быстрый typing и понятный progress без инфраструктурных подробностей | Checker source и live typing/PDF progress PASS |
| Измерение latency до/после, queue/retrieval/AI/delivery | До/после собраны и независимо сверены с БД |
| Очистка памяти, удаление документов, полный reset | Checker source PASS; настоящий reset ожидается |
| Owner/TTL/immutable approval, атомарность, повторы и аудит удаления | Checker source PASS; Reviewer source APPROVE |
| Файловые гонки, новые данные и восстановление после рестарта | Checker source PASS; Reviewer source APPROVE |
| Продолжение клиентской приёмки после подтверждённого reset | Ожидается настоящий owner callback |

Доработка опубликована в [PR2](https://github.com/ural-byte/5523789-chief-ai-assistant/pull/2),
обновлённый бот [доступен](https://t.me/UralbyteDemoBot). Source gates: 122 теста +
14 независимых случаев PASS, Reviewer APPROVE; live latency/progress сверены с БД.
[Фактическая поставка](deployment/bigbang-uralbyte8.md). PR не слит; настоящая очистка
требует owner approval. Клиентская приёмка продолжается, вердикт не меняется.

## Blocking-дефект: URALBYTE-9

[Отдельный тикет](https://tracker.yandex.ru/URALBYTE-9) и
[диагностика](followups/URALBYTE-9.md) фиксируют зависание при выборе актуальной
версии памяти. Подтверждённая причина видимого зависания — whitespace-only final,
принятый как выполненная операция, и бесконечные повторы Telegram HTTP400.
Выборочное удаление устаревшей записи также отсутствовало.

| Проверка исправления | Состояние |
|---|---|
| Точный выбор старой и актуальной записи из реального конфликта | Read-only frozen helper compatibility PASS; настоящий Telegram flow ожидается |
| Общее destructive approval, cancel, owner/chat/TTL, immutable payload и повтор confirm | Свежие Checker source PASS, Reviewer APPROVE |
| Deadline обработки, зависший AI/tool/job и защита от поздних результатов | Checker source PASS, Reviewer APPROVE; live проверяется отдельно |
| Непустой final, конечные повторы доставки и восстановление ранее зависшей операции | Checker source PASS; live recovery PASS, один фактический Telegram ACK без replay |
| Telegram: вопрос → выбор → точная карточка → настоящий owner confirm → повторный вопрос | Ожидаются настоящие сообщения и подтверждение владельца; бот обновлён |
| Продолжение клиентской приёмки с теми же записями | PENDING; reset до этой проверки не выполняется |

Клиентский вердикт не меняется. Блокировка снимается только после повторной проверки
этого flow на доступном боте. Ранее подтверждённые результаты URALBYTE-8 сохраняются
отдельно; неподтверждённый reset не выдаётся за выполненный.

После разрешённого пользователем дополнительного цикла: 292 теста и 68 независимых
проверок PASS, Reviewer APPROVE с 24 собственными проверками. Обход через
sentence-valued entity/narrator/selector закрыт. CI проверенного source commit,
развёртывание и независимый live recovery PASS. [Поставка](deployment/bigbang-uralbyte9.md).
Настоящий owner flow ещё ожидается; клиентский вердикт остаётся PENDING.

## Определение намерения сохранить: URALBYTE-10

[Доработка](followups/URALBYTE-10.md) исправляет отказ на «Привет! Запомни: меня
зовут Вова.»: backend больше не определяет намерение позиционным regex. Основной
LLM выбирает `save_memory`, получает фактический результат инструмента и готовит
ответ. Backend сохраняет проверки аргументов, владельца, идемпотентности, deadline
и удаления данных.

Свежий Checker source PASS: 325 тестов, 11 собственных проверок и 4 настоящих
Yandex сценария. Reviewer APPROVE, два собственных adversarial теста PASS.
[PR4](https://github.com/ural-byte/5523789-chief-ai-assistant/pull/4) и exact-head CI
прошли; source обновлён в bigbang, данные сохранены. [Поставка](deployment/bigbang-uralbyte10.md).
Genuine owner Telegram
save → итоговый ответ → последующий поиск пока не проверен. Клиентский вердикт
PENDING и блокировка демонстрации по URALBYTE-9 остаются без изменений.

Состояние исходной пары конфликтующих записей в старом отчёте URALBYTE-9 относится
к моменту той поставки. Read-only проверка 2026-10-05 06:36 UTC после последующих
настоящих пользовательских операций уже не обнаружила обе записи. Это не считается
доказательством прохождения полного клиентского flow разрешения конфликта.
